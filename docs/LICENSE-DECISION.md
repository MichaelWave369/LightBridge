## What this does and does not cover

- The MIT license in the repository root covers **original LightBridge code and documentation owned or licensable by its contributors**, unless another license or source notice identifies an exception.
- Third-party works and their separate attribution/license obligations **remain in effect**. MIT does not overwrite or relicense somebody else's code.
- The recovered v0.1.0 candidate's `LICENSE-NOTICE.md` says *no project license was selected*. This is a **historically accurate statement at the time of that candidate**. Retain the file unchanged in the archived source snapshot. This decision supersedes that historical status **only for original, authorized project code moving forward**.
- The recovered v0.1.0 candidate's `THIRD_PARTY_NOTICES.md` identifies the `vendor/QRCode-src/` and generated `vendor/qrcode-browser.js` as adapted from `qrcode-terminal`, with its `vendor/LICENSE-qrcode-terminal-Apache-2.0.txt`; original QRCode implementation headers also identify Kazuhiko Arase and MIT terms. When importing, keep those upstream headers, notices, and license files unmodified and review redistribution requirements.
- A root software license does **not** establish rights to unrelated research papers, diagrams, photos, trademarks, or materials that the repository does not own.
- Open source status does **not** mean implementation is released, secure, production-ready, or tested on physical devices.

## Application on future source import

1. Keep both recovered ZIPs and each original file byte-for-byte intact as an auditable recovery source.
2. Put a clear pointer to this later licensing decision alongside the imported source, without changing the historical candidate's `LICENSE-NOTICE.md`.
3. Retain all third-party notices and applicable license text.
4. Validate provenance for any files not confirmed as original LightBridge work before publication.
